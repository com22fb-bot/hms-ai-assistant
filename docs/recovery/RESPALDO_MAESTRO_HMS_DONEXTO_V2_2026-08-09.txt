5. PROBLEMAS RESUELTOS (RESUMEN OPERATIVO)
================================================================================

OAuth / Gmail
- Consent Google en Testing vs Production / test users.
- Redirect Railway HTTPS vs http insecure_transport (force HTTPS en callback).
- OAUTH_ENCRYPTION_KEY faltante (tokens no se guardaban).
- Códigospace vs donexto.com como redirect (ops docs).

Yahoo
- No OAuth; IMAP + app password.
- Middleware auth faltante en /auth/yahoo (corregido).
- Deactiva otros providers al conectar.
- Errores y UX de contraseña de aplicación clarificados.
- Antifill de credenciales del login Donexto en form Yahoo.

Frontend / Deploy
- UI “vieja” en producción = falta `npm run deploy` Cloudflare (Worker).
- Wrangler OAuth timeout en Codespace: usar CLOUDFLARE_API_TOKEN.
- Token mal pegado en export (invalid header Bearer …).
- Shell `>` por comillas abiertas (Ctrl+C / una línea a la vez).

Producto / UX
- Login con scroll / form abajo: rediseño viewport-fit (dx-auth).
- Dashboard “laboratorio de controles / En prueba”: limpia UI.
- Métricas en cero: son de casos clasificados, no del inbox crudo.
- Cambiar buzón: acción lateral “Cambiar buzón” añadida.
- Identidad: login Donexto ≠ correo de buzón.

Push / VAPID (detalle en sección 8)
- Confusión de nombre de archivo: no vapid.env sino push.env.
- path parents[2] generaba secretos fuera del repo; corregido a parents[1].
- Variables exactas: HMS_VAPID_PUBLIC_KEY, HMS_VAPID_PRIVATE_KEY_PATH,
  HMS_VAPID_SUBJECT.

8. PUSH / VAPID — DIAGNÓSTICO Y PROCEDIMIENTO
================================================================================

8.1 Hallazgo exacto (Codespace / diagnóstico propietario)

Backend lee SOLO:
  HMS_VAPID_PUBLIC_KEY          (string base64url de clave pública P-256)
  HMS_VAPID_PRIVATE_KEY_PATH    (ruta a archivo PEM EC privada)
  HMS_VAPID_SUBJECT             (default mailto:hmcelinfo@gmail.com)

Archivos del generador scripts/generate_vapid_keys.py:
  .hms-secrets/vapid_private.pem
  .hms-secrets/push.env
NO crea: vapid.env ni .hms-secrets/vapid.env (nombre incorrecto a buscar).

Idempotencia del generador:
  Si existen private_path y env_path → imprime VAPID_KEYS=EXISTING y exit 0.
  Si no → genera PEM + push.env (chmod 600).

Ruta de repo en script (actual en main):
  repo = Path(__file__).resolve().parents[1]
  → /workspaces/hms-ai-assistant

Bug histórico corregido:
  parents[2] escribía en /workspaces/.hms-secrets (fuera del repo).
  Buscar ambas ubicaciones al recuperar llaves existentes.

Código:
  backend/app/services/push_service.py  (_public_key, _private_key_path, _subject)
  backend/app/services/web_push_sender.py  (_load_vapid_private_key, envío VAPID)
  configured := bool(public_key AND private_key_path)

8.2 Procedimiento recomendado (solo cuando el propietario autorice generar)

1) Localizar llaves existentes en:
   /workspaces/.hms-secrets/push.env + vapid_private.pem
   o $ROOT/.hms-secrets/...
2) Si no existen: corregir parents[1], mkdir .hms-secrets 700, gitignore,
   python3 scripts/generate_vapid_keys.py (NO ejecutar sin autorización en prod).
3) source push.env; reiniciar uvicorn con env cargado.
4) Validar /health 200 y panel Push: servidor configurado / activo.
5) NO enviar “prueba” hasta que la UI reporte llaves configuradas.
6) Nunca commitear .pem ni push.env.

8.3 Railway / producción
- Exponer HMS_VAPID_* vía variables de entorno o montaje de secreto de path.
- Public key también al frontend si el flujo de suscripción la requiere
  (según endpoint de configuración push del backend).

13. MERCADO EE.UU. — CONCLUSIÓN EJECUTIVA (V2.1)
================================================================================

Fuente: síntesis de comportamiento de consumidores EE.UU. aportada 2026-08-09
(hipótesis de trabajo; validar con fuentes primarias antes de claims públicos).

13.1 Fatiga y preferencias de notificación

INBOX FATIGUE alto → solo alertas inmediatas con utilidad práctica,
financiera o de seguridad en tiempo real.

Nivel 1 — Altamente preferido (80–90%+ aceptación) — PUSH INMEDIATO
- Finanzas y pagos (transferencias, recibos, facturas, cobros)
- Seguridad / 2FA (códigos, login nuevo, cambio contraseña)
- Logística y envíos (Amazon, FedEx, UPS, USPS) + viajes/vuelos

Nivel 2 — Moderado (40–60%) — digest / opt-in
- Agenda/citas, servicios
- Menciones trabajo/VIP en colaboración (Slack, Workspace, Jira, Teams)
- Precio/stock en wishlists (configurado)

Nivel 3 — Rechazo (<20% aceptación; >75% evita push de promo)
- Batch-and-blast, newsletters, promo general → spam folders / silencio
- ~80% silencia si irrelevancia o demasiada frecuencia

13.2 Correo personal / familiar (no laboral)

- Tiempo personal: ~1.5–2.5 h/día (laboral 3+)
- 90% revisa personal en horario laboral; 25% en primeros 5 min al despertar
- 86% mantiene ≥3 cuentas personales (Principal / Comercial / Spam-registros)
- >60% volumen = boletines/ofertas; solo ~37% percibido útil
- Prioridad hogar: cargos/tarjeta/hogar ~90%; paquetes (porch piracy) ~85%;
  escuela/hijos ~80%; viajes familiares ~78%
- Lectura: smartphone 75–85%; desktop 15–20%; tablet/watch 5–10%
- Proveedores uso personal: Gmail ~78%; iCloud ~30–35%; Yahoo ~28%;
  Outlook/Hotmail ~20%

13.3 Impacto para el SaaS B2C/Family

Argumento de venta:
  “Tu asistente de logística y finanzas del hogar”
  (paquete, cargo raro, aviso escolar) — NO “gestionar correo”.

WTP: ~USD 4.99–9.99 / mes por utilidad familiar.

Canal: Push (o SMS/WhatsApp en el futuro) >> reenviar por email.

Implicación de producto (orden de build):
1) Taxonomía N1/N2/N3 + política push
2) Home personal: pila N1; ruido colapsado
3) Push solo N1 + quiet hours + dedupe
4) Gmail estable (+ Yahoo ya en camino); multi-cuenta roles después
5) Copy EN + Stripe band WTP; Family cuando DoD Profesional/Push OK
